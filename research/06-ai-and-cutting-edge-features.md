**Category: AI as a digital general manager**

Lavu's Marty is the most ambitious multi-agent AI in any POS:

  1. **Promo agent** — identifies slow periods, creates targeted promotions automatically

## Cross-Cutting AI Themes to Build

### 1. Dynamic Pricing Engine
- Rules-based dynamic pricing (happy hour, peak demand, event-based)
- AI-driven dynamic pricing (surge pricing like Uber, demand-based)
- **Leaders**: None have fully deployed this yet — huge opportunity
- Wendy's piloted it in 2024, pulled back due to PR backlash (framing matters)
- **Right approach**: Frame as "discounts in slow periods" not "surge in busy periods"

### 2. Waste Intelligence
- Predict waste before it happens based on prep decisions vs. expected orders
- Alert kitchen: "You prepped 40 portions of salmon. Based on tonight's reservations, you'll likely sell 28. Consider holding 12 portions."
- **Leaders**: Lavu Marty doing this; no one else at scale

### 3. Staff Performance AI
- Identify your best servers (highest check size, best tips, fastest table turn)
- Identify struggling servers with specific data
- Auto-generate coaching recommendations
- **Leaders**: SpotOn partially; nobody does this fully

### 4. Natural Language Reporting
- "How did we do last Friday vs. the Friday before?"
- "What's my most profitable item this month?"
- "Which shift is my highest labor cost?"
- No POS should require anyone to build a report — just ask.
- **Leaders**: Toast IQ closest; all others trailing

### 5. Computer Vision / AI Camera Integration
- Count customers in queue → alert staff to open new register
- Detect queue length at drive-thru → adjust digital menu board offers
- Monitor table cleanliness → alert bussers
- **Leaders**: Emerging in QSR (McDonald's experiments) but no POS has this natively

### 6. Sentiment Analysis
- Analyze Google reviews, Yelp reviews, delivery app reviews in real time
- Alert manager when negative review posted
- Identify trending complaints ("service was slow" appearing repeatedly)
- **Leaders**: SpotOn partially; most use third-party tools

## Offline-First Architecture Deep Dive

### Why Offline Matters More in Africa
- Power outages more frequent
- Internet connectivity less reliable
- Mobile data costs limit always-on cloud reliance

### Architecture Approaches

#### Toast Approach: Cloud-First with Local Cache
- Transactions cached locally when offline
- Synced to cloud on reconnect
- Works for short outages (minutes to hours)
- Limitation: extended outages can cause complexity

#### TouchBistro Approach: Local Server + Cloud Sync
- Mac mini server on-premises
- ALL data processes locally first
- Cloud syncs in background when available
- Works for indefinite offline periods
- Limitation: local server is additional hardware/complexity

#### Revel Approach: Hybrid
- Local processing + cloud sync
- Similar to TouchBistro but on iPad ecosystem

### Best Practice for African Markets
**Goal**: Full functionality for 72 hours without internet
**Architecture**:
1. Local SQLite/PouchDB database on each terminal
2. All transactions written locally first, queued for sync
3. Conflict resolution logic for when multiple terminals go offline and reconnect
4. Card processing: store encrypted card data locally, process when connectivity returns (or use a local card processing device)
5. Inventory: local copy of current inventory, reconcile with central on reconnect
